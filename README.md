# RTL Agent

Describe a small digital circuit in plain words and an AI designs it. Checking tools then test the design, and if it fails, the AI is shown the errors and tries again.

**[Try it here](https://rtl-agent-seven.vercel.app)** (no install or API key needed; the first load can take about a minute)

How this was built and what went wrong: [development story](docs/Dev-story.md)

## How it works

RTL Agent uses compiler and simulation feedback to help an LLM fix small hardware designs. The current focus is building blocks used in CPU, GPU and NPU architectures.

The tool takes a written circuit specification, asks OpenAI for a testbench and SystemVerilog, then runs Verilator, Icarus Verilog and Yosys locally. If a check fails, it sends the diagnostics back to the model and requests an RTL repair. The testbench is generated in a separate call before the RTL and stays the same throughout those repairs.

## Website

**Live** lets you enter a circuit specification and see the generated design, verification results, waveforms and synthesis metrics without installing the tools locally. No API key is needed from visitors. There are 20 Live runs available per day across everyone, resetting at midnight Singapore time.

**Replay** lets you inspect recorded CPU, GPU and NPU examples without using the daily allowance. These examples were written in advance (not generated live), but the checks were run with the same tools.

The frontend runs on Vercel, and the backend runs on Render.

## Evaluation

I tested RTL Agent using [VerilogEval](https://github.com/NVlabs/verilog-eval), splitting its 156 problems into 56 development problems and 100 reserved for an evaluation. I checked for overlap and kept detected duplicates together.

The development run helped identify problems with generated testbenches, clock timing and latch handling. After reviewing those results, I removed a local timing-prompt experiment and used the published version at commit `644b117` for the remaining 100 problems. No code or settings were changed during that evaluation.

Both runs used GPT-6 Luna, with one trial per problem and up to three RTL candidates. The agent generated its testbench before seeing the RTL and kept it unchanged during repairs. 

| Measure | evaluation |
|---|---:|
| Problems selected | 100 |
| Problems evaluated | 98 |
| First RTL draft passed official tests | 84/98 — 85.7% |
| Agent accepted RTL that passed official tests | **80/98 — 81.6%** |
| Any saved candidate passed official tests | 88/98 — 89.8% |
| Agent PASS on failed tests | 10 |

Two problems in each group failed reference preflight and were recorded separately as benchmark errors. 

The main result is **81.6%**. Although 88 problems had a passing candidate, eight were rejected or stopped by the agent’s own checks. The ten false PASS results also show that passing a generated testbench does not guarantee correctness.

## Rationale

Simply using an AI in a chatbot environment may generate hardware designs that look correct. However, in reality, they may be incorrect since they were not checked.

The design generated by the agent only counts as passing if it is verified by the checking tools. The test is generated before the design and can't change during repairs, so the AI can't pass by quietly changing the test.

## Glossary

- **RTL / SystemVerilog:** RTL describes a digital circuit as data moving between storage points on every clock tick; SystemVerilog is the language it's written in.
- **Testbench:** a small program that feeds a design test inputs and checks its outputs. Think of it as the answer key.
- **Yosys:** an open-source tool that turns a design into basic logic building blocks and counts them, to show roughly how much hardware it needs (not real chip size or speed).
- **VCD:** a file that records how every signal changes over time during a test, which the waveform viewer draws.
- **Latch:** an accidental memory element created when a design doesn't say what an output should be in every case, which is usually a bug.

## Examples used in replay

- An 8-bit CPU ALU with arithmetic, logic, shifts and status flags.
- An 8×16-bit register file with a hardwired zero register.
- A four-lane GPU SIMD ALU with per-byte saturation.
- A pipelined pixel alpha-blending unit.
- A signed INT8 NPU MAC with a 20-bit accumulator.

The specifications are in `examples/`. These are individual blocks (not complete chips).

## Local setup

Requires Python 3.11+, Icarus Verilog, Verilator and Yosys. On macOS:

```bash
brew install icarus-verilog verilator yosys
git clone https://github.com/Rapidonot/rtl-agent.git
cd rtl-agent
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev,web]'
rtl-agent doctor
```

Set `OPENAI_API_KEY` in your terminal, then choose a model. (I recommend GPT-6 Luna as it was found to be cheap compared to Sol and Astra while still being competent during testing)

```bash
rtl-agent generate --spec-file examples/npu_neural_mac.txt --top npu_neural_mac --model YOUR_MODEL_ID --max-attempts 3
```

Runs save source files, logs and reports under `runs/`; waveforms are saved when produced.

To run the website locally:

```bash
rtl-agent serve
```

Open `http://127.0.0.1:8000`. For local Live generation, also set `RTL_AGENT_MODEL` to your chosen API model ID in the server terminal.

## Verification

A candidate must pass Verilator lint, Icarus compilation and simulation, and Yosys synthesis. The testbench must finish its checks and print `RTL_AGENT_PASS` exactly once.

Assertion failures, timeouts, truncated logs and inferred latches count as failures. Repairs can replace only the RTL; the testbench stays unchanged throughout the repair loop.

Yosys reports gate counts, flip-flop counts and logic depth. When a simulation fails and a waveform is available, the last 12 moments of the waveform are included in the repair prompt.

## Testing without an API

The repo includes tests that use simulated model responses. Run the tests with:

```bash
pytest -q
```

The tests run EDA tools on an NPU MAC fixture, including designs with deliberate logic, syntax and latch defects. They also check the web API, session ownership and daily run limit. Model responses are simulated in the automated tests, so pytest does not use the API.

## Things to note

- When the 20 daily runs are used up, Replay mode still works.
- The backend on Render is on a free tier, so it may take about a minute to wake up if it has been inactive.
- Prompts entered in Live are sent to OpenAI, so they shouldn't contain personal information.
- Passing the checks is strong evidence that a design works, not a formal proof. Since the AI writes the test too, a bad test could let a bad design through.
